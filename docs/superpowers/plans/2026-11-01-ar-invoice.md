# 应收开票关联实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在已确认应收基线上实现独立开票口径、调整后开票、原关联撤销及可追溯的蓝红字关联。

**Architecture:** 复用finance事务、幂等请求和生命周期流水；开票分配独立于核销分配。原应收和原税率不可覆盖，新的调整应收与原应收关联后再校验开票资格。表结构只承载来源与分配；额度和外部发票状态由服务校验，不声称SQL能独立验证跨表金额守恒。

**Tech Stack:** Java21、Spring Boot3.5、MyBatis-Plus、MySQL8.0.42、JUnit5。

## 业务边界与实施选择

基线已确认且用户要求直接依次实施。本计划是工程细化，不重启业务确认流程。

- 收款/核销不消耗开票额度；已结清应收仍可关联发票。
- 2026-11-01用户明确采用：关联负数按原业务组、价税类型和税率计算开票调整，不跟随实际抵销目标；开票额度按该口径归集。
- 税率或税额与待开票应收不一致时拒绝直接改写；先通过原有应收创建及调整关联处理。税率变更保留旧税率快照，新税率由新应收承载。
- 发票关联记录包括外部来源系统、ID、编号、日期和分配行；本系统不冒充税务开票平台，不发送实际税务开票请求。
- 蓝字/红字作为关联方向独立保存。红字必须指向同范围原蓝字发票及原分配；红字额度受原已开票关联和调整应收双重约束。关联撤销不删除记录，也不等同对税务平台作废。
- 汇率差异行默认不可开票；后续通过显式业务配置放开，不能依靠普通价款类型默认允许。
- 账户转入/抵扣、收款核销金额不会被开票动作修改。
