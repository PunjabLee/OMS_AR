# 应收作废 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 有权限的财务或所属上游直接作废应收，保留历史、解除前置依赖并防止隐式重建。
**Architecture:** finance事务内保存状态、余额快照及来源拦截；所有创建/作废遵守来源→单头（作废）→有序业务组→行的锁序。使用独立来源键而非事件编号识别被取消的业务。
**Tech Stack:** Java21、Spring Boot3.5、MyBatis-Plus、MySQL8.0.42、JUnit5。
**Spec:** ../specs/2026-10-31-ar-project-design.md

## Global Constraints

原额/税率/来源不可删除；作废余额为0，不伪造核销。无审批，原因必填，服务端校验主体与动作权限。GET/POST对象协议、显式审计与完整事务流水。用户已要求直接依次实施，无需重新确认执行方法。

## Review Focus

- 换事件编号重推同一来源不能重建；不同来源行不被误拦。
- 同时创建/作废与核销不能留下有效分配指向VOID行。
- 组共享开票额度不能因移除未开票正数而低于已有开票净额。
- 上游不能自报来源系统越权作废其他系统数据。
- 有效调整指定原行时不能孤立该调整；历史/已撤销关联保留可查询。

## 9a：来源锁与禁止隐式重建基础

Files: scratch/dbddl/V010__ar_source_guard.sql；domain/entity/finance/ArSourceGuard.java；mapper/finance/ArSourceGuardMapper.java；dao/finance/ReceivableDao.java及impl；ReceivableServiceImpl；SourceGuardRealTest；scripts/test-mysql-source-guard。

来源键为legalEntityId/system/type/id/lineId（NULL单独编码），不含事件编号或输出键；哈希由服务按JSON数组SHA256生成，表内保留原字段并做碰撞核验。多个价税输出共享来源锁。不同主体/来源行隔离。无行号代表单据级来源槽，不与具体行混淆。无显式解除拦截/重建入口，不允许自动恢复作废记录。

Files: ReceivableVoidService/Impl、ReceivableVoidDao/Impl、DTO、Controller、VoidRealTest及HTTP。
