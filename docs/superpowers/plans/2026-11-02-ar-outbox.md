# 财务通知实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement task-by-task.

**Goal:** 业务事件原子入队，后台至少一次投递，支持失败重试和查询。
**Architecture:** outbox保存事件/主体/逻辑目的地/不可变payload；派发运行状态与财务流水分离。默认不外发，接收地址和凭据仅由服务端配置，接收方按eventId+destination幂等。不宣称跨系统事务或严格一次投递。
**Tech Stack:** Java21、MySQL8.0.42、Spring事务、JDK HTTP客户端。
**Spec:** ../specs/2026-10-31-ar-project-design.md。

## 12a 存储约束
- [x] V011：事件/目的地唯一，主体正数；PENDING/PROCESSING/RETRY/SENT/DEAD；attempt_count非负；租约token/until成对且仅处理中存在；SENT必须有sent_time。
- [x] 实库失败后实现，验证重复、状态、租约、外键、重试字段；全量回归后单独提交。

## 12b 原子入队
- [x] FinanceJournal与创建路径均将事件和完整变化payload同事务入队；显式传递主体，不从不可信文本推断。
- [x] 首期固定逻辑目的地FINANCE_EVENTS，按主体配置可信集成接收端；默认未配置时保留队列不发送，不把业务请求中的URL作为目的地。
- [x] 验证幂等重放、故障回滚、所有业务事件及完整payload，提交。

Ruling: 12b同时修复快照小数精度：实库证实JSON数值将9999999999999999.12345678舍入为1e16，导致通知无法保真。新事件快照升级版本2，小数用十进制文本保存；历史版本1保留，消费者需兼容该表示。业务DECIMAL金额及幂等摘要不改。
