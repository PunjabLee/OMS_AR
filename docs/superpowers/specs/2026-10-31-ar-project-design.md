# 应收系统工程设计基线

状态：业务基线已由用户确认；新建工程，MySQL 8.0.42。本文中的工程命名为实施默认值。

## 工程边界

- Java 21、Spring Boot 3.5、MyBatis-Plus、Maven 父子模块。父项目 oms-ar，服务模块 oms-ar-server，包根 com.punjab.oms.ar。
- 遵循根 AGENTS.md 分层、DTO/Query/BO/VO 边界、自增主键、显式审计及测试要求。
- 用户最新指示取消 Nacos 地址：新工程不引入 Nacos 配置中心，不使用指南中的旧地址；本地 application.yml 配合环境变量。暂不增加服务注册依赖。
- 数据库连接通过 DB_URL、DB_USERNAME、DB_PASSWORD 注入；禁止硬编码密码。默认测试不连接业务数据库。
- 本期建设后端服务与接口契约，不因接口设计而推定已实现前端。

## 已确认业务基线

1. 上游或直接创建应收，成功即生效，不审核。
2. 价款、销项税独立成行；统一金额字段，通过 amount_type 区分。应收、核销、转出、剩余、开票仍为独立金额口径。
3. 独立业务组可仅有税额；业务组跨单关联，允许在结清后补税，不改历史核销。
4. 首期按组依次先税后价，预留整单先税后价但不允许提前启用。
5. 有关联负数应收优先原行、同类型抵销；不足可由用户拆分为其他同类型抵销、转余额、待核销。
6. 无关联负数按原核销顺序抵销，可跨价税类型，不改变原明细性质。
7. 最小客户信用余额按客户、主体、币种隔离，支持来源批次、转入、抵扣和撤销，不计入实收。
8. 开票差异先由调整单或上游生成调整应收，按需核销后再开票。开票额度不等于未收余额。用户于2026-11-01进一步确认：关联负数调整按原业务组、价税类型及税率影响开票额度，不跟随实际抵销目标改变开票归属。
9. 汇率差异按结算币种形成实际应收，归价款类并保留业务类型和计算依据。
10. 来源记录类型、编号、ID及可选行ID；生命周期保存初始化及所有业务事件的金额、税率前后变化。
11. 上游与财务可作废；财务有权限、原因必填、无审批，先解除有效核销、划转和开票关联。

## 设计方案选择

采用明细余额＋完整业务流水。相比只维护余额，更能支持反核销、跨单关联和审计；相比全事件重建，查询与开发成本较低。单据、分配明细及流水同事务提交。

## 事务与接口

Service 负责事务，跨模块仅调用 Service，不跨 DAO。所有写动作具有幂等键，保留请求摘要：同键同内容返回原结果，同键不同内容报冲突。

核销预览不占款；确认重新检查每条余额、版本和用户分配，变化则返回冲突。写入按固定ID顺序锁定，关联对象使用相同事务管理器。外部系统通知通过本地待发送事件重试，不声称跨系统事务。

接口根 /api/finance，资源为 receivables、settlements、customer-balances、invoice-links。分页 POST /page、详情 GET /detail；create、preview、confirm、reverse、void 等写动作均 POST 对象请求体。返回 ApiReturn，分页 PageResult。不开放任意余额 update 或流水 delete。

## 验收与限制

必须验证重复请求、反核销、跨币种拦截、权限隔离、后补税额、余额批次使用、并发作废/核销及开票口径独立。真实 MySQL 测试单独门禁，不用 H2 测试声称验证了 MySQL 锁语义。

本期不含提现退款、跨客户转账、跨币种抵销、税务申报及自动记账凭证。汇率差异可开票范围由业务配置明确，不自动默认为可开票。
